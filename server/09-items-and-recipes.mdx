## Data components

Every item table (the argument of `inventory:set`, `inventory:add`, menu items) and every item read back
(`inventory:get`, `inventory.held`) has an optional `components` field: a map from a component name to its value
written as SNBT text. These are the vanilla data components in their datapack form: `custom_name`, `lore`,
`enchantments`, `custom_model_data`, `unbreakable`, `attribute_modifiers`, `custom_data`, `profile`,
`potion_contents` and the rest.

```lua
player.inventory:set(0, {
  id = "minecraft:stick",
  components = { ["minecraft:custom_model_data"] = "{floats:[3.0f]}" },
})
```

The older `name`, `lore`, `damage` and `enchantments` fields keep working, and win over the same component in
`components`.

## Recipes

`recipes` registers and removes recipes written in the datapack's own JSON: shaped, shapeless, smelting, blasting,
smoking, campfire cooking, stonecutting, smithing and transmute.

| Call | Does |
|---|---|
| `recipes.add(id, json)` | Registers a recipe; `false` when the id is taken or the JSON is not a recipe |
| `recipes.remove(id)` | Takes a recipe, the server's own included, out of every lookup |
| `recipes.has(id)` | Whether it exists |
| `recipes.ids()` | Every id: the datapack's first, then the added ones |
| `recipes.clear()` | Empties the list |
| `recipes.reset()` | Puts back the datapack's recipes and drops the added ones |

```lua
recipes.add("myplugin:ruby_block",
  '{"type":"minecraft:crafting_shapeless","ingredients":["minecraft:diamond"],"result":{"id":"minecraft:stone","count":1}}')
```

## Events

| Event | Fields |
|---|---|
| `inventory.drag` | Cancellable. `player_name player_uuid world type slots`; `type` is `even`, `single` or `clone`, `slots` is `12,13,14`. Fired once when the player lets go |
| `inventory.changed` | `player_name player_uuid world`. After every click on a window a plugin opened and may edit |
| `inventory.prepare` | `... kind recipe result name cost`; `kind` is `crafting`, `anvil` or `smithing`. `result` (an item as SNBT, empty for none) and `cost` (anvil levels) can be written |
| `inventory.take` | Cancellable. `... kind recipe result shift`; `kind` adds `grindstone` and `stonecutter`. A result slot is about to be taken |
| `inventory.enchant_prepare` | Cancellable. `... item bookshelves offers`; `offers` is `id\|level\|cost` for each of the three rows joined by `;`, writable |
| `inventory.enchant` | Cancellable. `... item button cost enchants`; `cost` and `enchants` (`id:level,id:level`) are writable |
| `furnace.burn` | Cancellable. `world x y z cooker fuel burn_time`; `burn_time` is writable |
| `furnace.start` | `world x y z cooker source total recipe` |

Block entity data a plugin can write with the block entity NBT calls: a furnace saves `Paper.CookSpeedMultiplier` (0 to
200, higher is faster; it multiplies the fuel speed at once and keeps the progress), a beacon `BeaconRange` (double)
and a beehive `MaxBees` (int) override the effect range and the occupant limit.

Existing events changed:

- `inventory.close` has a new `reason` field: `player`, `plugin`, `open_new`, `disconnect`, `death`, `teleport` or
  `unknown`. It now fires for every window that closes, not only when the client sends the close packet.
- `inventory.open` now fires for chests, barrels, shulker boxes, hoppers, dispensers, droppers, ender chests,
  enchanting tables, anvils, smithing tables, grindstones, looms, cartography tables, stonecutters, beacons, crafters,
  merchants and mounts. `kind` is the window name.
- `inventory.smelt` fires once when a smelt finishes, with the new fields `source`, `output` (SNBT, writable) and
  `recipe`.

```lua
on("inventory.prepare", function(e)
  if e.kind == "anvil" then e.cost = 1 end
end)
```
