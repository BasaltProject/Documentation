Plugins are written in Lua and packaged as `.bspkg` files, each with a manifest,
code, resources and metadata. This is the API of the project: everything the
server can do, it can do through here.

## A first plugin

```lua
-- src/main.lua
on("player.join", function(e)
    e.player:send("<gradient:aqua:green>Welcome!</gradient>")
end)
```

Text is authored in MiniMessage and rendered through the component model, never
through legacy colour codes. Colours, hovers, clicks and translations are all
part of the component, not part of a formatted string.

## The sandbox

Every plugin runs inside a sandbox with a per-tick instruction budget. A plugin
that loops forever is stopped and reported; it does not take the server with it.

<x-docs.callout type="tip" title="Why Lua">
The runtime is the official Lua 5.5.1, built from source into the binary, so it
is the same runtime everywhere Basalt runs. There is no Lua to install alongside
it and no per-platform build of your plugin.
</x-docs.callout>

## Packaging

A `.bspkg` is a directory tree with a manifest at its root:

```toml
id = "hello"
name = "Hello"
version = "1.0.0"
main = "src/main.lua"
```

Drop the package in `plugins/` and start the server.

Kiln, the plugin compiler, checks a plugin before it reaches a server: `kiln check hello` reports a misspelt name
such as `players.onlin`, a missing `require` or a broken `plugin.toml`.

## Errors

A defective plugin is a plugin problem, never a server problem. Failures are
reported with the plugin that caused them and the server keeps running.
