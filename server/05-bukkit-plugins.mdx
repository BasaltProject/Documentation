---
title: Bukkit plugins
description: Running the existing ecosystem through Basalt Shim, and how it works.
---

Most of the Minecraft server ecosystem consists of Bukkit, Spigot and Paper plugins that
will never be rewritten. Basalt aims to support them optionally without requiring an external JVM.

## How it works

Bukkit plugins do not run inside the native server core. They are executed through
**Basalt Shim**, a lightweight embeddable C++ Java virtual machine developed for modern Java
LTS releases. The bridge communicates with the core over IPC, ensuring the Basalt binary
remains free of JVM overhead when the feature is disabled.

```
basalt (native)  <--- IPC --->  bukkit bridge (Shim)
```

<x-docs.callout type="note" title="No external Java runtime required">
Because execution is powered by Basalt Shim, operators do not need to install an external
JDK or configure a host Java binary path. The feature is opt-in and off by default.
</x-docs.callout>

## Enabling it

```toml
[bukkit]
enabled = true
memory = "2G"
```

With `enabled = false`, which is the default, none of this exists at runtime.

## When to use which

| You want | Use |
|---|---|
| Maximum performance, native execution | Native Lua plugins |
| Existing legacy plugins | The Bukkit bridge (Basalt Shim) |
| Both | Both, running side by side |

Native plugins are the fast path: no process boundary, no serialization, and no
secondary heap. The bridge exists so that adopting Basalt does not require giving up
the plugins your server relies on while you migrate.
