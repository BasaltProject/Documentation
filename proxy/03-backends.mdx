---
title: Backends and translation
description: Where version translation happens, and why the default is what it is.
---

Older Java clients and Bedrock clients are supported by translating at the edge,
and both the proxy and the server carry that machinery. That is deliberate, not
duplicated effort: the same translation can be done in either place, and which
one should do it depends on what is behind the proxy.

## The default

The proxy is always the one that opens the port and accepts the connection. It is
also the process with the most connections open at once, so translating every one
of them there is the most expensive place to do it. The default is to push that
work down when it can be pushed.

| Situation | Who translates | Why |
|---|---|---|
| Backend is Basalt Server | The server | The proxy is the connection-heavy process, and the two speak to each other well enough to hand the work over |
| Backend is anything else | The proxy | A vanilla or Paper backend only understands its own version, so the proxy has to do it |

## Overriding it

Both halves are configurable:

```toml
[translation]
# auto, proxy, backend or off
mode = "auto"
```

An operator who wants every connection translated at the proxy, or who wants it
never translated at all, says so here.

<x-docs.callout type="note" title="The table is a default, not a constraint">
`auto` is the behaviour described above. The other modes exist because a network
with an unusual shape knows its own load better than a default can.
</x-docs.callout>
