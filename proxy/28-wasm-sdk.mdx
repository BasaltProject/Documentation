The SDK ships with Kiln and is unpacked under `build/.kiln/` during a build. It wraps the host ABI in each language's naming, string and callback conventions. The host operations are the same; source-level conveniences and return types differ.

The C/C++ umbrella headers and Zig root bring areas together. Other languages import packages/classes they use. API pages use C++ names; each language guide gives the actual conventions for entry points, strings, callbacks and optional values.

## Shared types

`core::Player` and `core::Ctx` are integer handles, with 0 invalid. A context identifies the current callback and expires when it returns. A player handle survives backend changes but expires when the player leaves the proxy. Reconnecting creates a new handle.

C++ handlers are plain functions taking `core::Ctx`. Register them in `plugin_init`. Other languages use their equivalent `init` entry point and callback type; Kiln supplies the exported trampoline. Do not export a standalone operating-system main function as a substitute.

Priorities run from lowest to highest for event processing. The default priority is `core::kNormal`. Permission-provider priorities have their own ordering, described on [Permissions](/docs/proxy/wasm-permissions), and should not be confused with event priorities.

## Strings and buffers

C/C++ input strings are NUL-terminated. Output APIs often take an explicit buffer/capacity and return a length or error; a length is not automatically a NUL-terminated string. The C++ `Text<N>` helper exposes `ok()`, `length` and `c_str()` and can truncate long replies to its fixed capacity.

Managed SDKs generally return their language's string/optional type and own the output allocation. Zig exposes slices and caller-selected buffers. Do not carry pointers into temporary output buffers into another callback.

Some operations return status 0, some a positive handle/count, and others 1/0 boolean decisions. A successful send means work was accepted; it does not prove the client displayed it. Read the particular function's contract.

## Errors

| Result | Meaning |
|---|---|
| `BASALT_OK` / 0 | Success for status-returning calls. |
| `BASALT_ERR_ABSENT` | No value, missing optional argument or no provider decision. |
| `BASALT_ERR_INVALID` | Invalid input, type, buffer or unsupported use. |
| `BASALT_ERR_STALE` | A context/player/request is no longer valid. |
| `BASALT_ERR_DENIED` | Required capability or operator grant is missing. |

A negative return code is an operation result, not a trap. Test it before using output. An out-of-bounds access or timeout is a module failure and follows the [execution model](/docs/proxy/wasm-execution-model).

## Named arguments and logging

Use `core::Args` to carry replacements such as `{name}` to message calls. In C++ it supports `args.add("name", value)`. Passing no args is different from assuming a proxy placeholder is automatically expanded; see [Text](/docs/proxy/wasm-text).

`log::log_debug`, `log_info`, `log_warn` and `log_error` emit plugin-prefixed lines. Use operational logs sparingly, especially in packet callbacks or while rejecting a flood. A log line per packet is itself a workload.

## Host ABI

Modules import shared functions from `basalt` and proxy-domain functions from `basalt_proxy`. SDK namespaces hide that split. The ABI uses wasm32 offsets into module memory, not native pointers; never persist an offset or host handle as a reusable identifier across reloads.

The [ABI reference](/docs/proxy/wasm-abi) describes imports and exports. Prefer rebuilding with the matching Kiln SDK instead of maintaining generated SDK files manually inside your project.
