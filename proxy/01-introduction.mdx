Basalt Proxy gives a network of Minecraft servers one public address. It authenticates players, chooses a backend, relays their sessions and moves them between servers without making them reconnect to the proxy. It is written from scratch in C++23 and distributed as a native executable, with no external JVM required.

A backend can be vanilla, Paper, Spigot, Fabric or [Basalt Server](/docs/server/introduction). Each has its own address, protocol and forwarding scheme. Basalt Server is optional; it can also take over translation that would otherwise happen on the proxy.

## Start with a working network

1. [Install the proxy](/docs/proxy/installation) and run it once to generate `config/`.
2. Define your servers and routes in [`servers.toml`](/docs/proxy/backends-and-routing).
3. Configure [identity forwarding](/docs/proxy/forwarding) on both ends. Keep the proxy in online mode and backend ports private.
4. Join through the proxy, then use `/server` to test changing backend.
5. Add [permissions](/docs/proxy/groups-and-permissions), [presentation](/docs/proxy/interface) and [plugins](/docs/proxy/wasm-plugins) for your community.

## What belongs on the proxy

| Area | What you control |
|---|---|
| [Routing](/docs/proxy/backends-and-routing) | Ordered routes, domain-specific destinations, server groups, fallback and health checks |
| [Client support](/docs/proxy/bedrock-and-versions) | Current and older Java protocols, Bedrock listeners and who translates |
| [Access](/docs/proxy/groups-and-permissions) | Proxy permission groups, whitelist and bans across the network |
| [Commands](/docs/proxy/commands) | Player and staff commands, aliases, custom text commands and replies |
| [Interface](/docs/proxy/interface) | Server-list profiles, backend status relay, tab list, sidebar, boss bar and animations |
| [Antibot](/docs/proxy/antibot) | Origin reputation, attack detection, limbo checks, captchas and verified players |
| [Remote administration](/docs/proxy/remote-api) | Authenticated HTTP reads and restricted send, kick and reload actions |
| [Operations](/docs/proxy/operations) | Monitoring, resource limits, reload, updates, backups and troubleshooting |
| [WASM plugins](/docs/proxy/wasm-plugins) | Network events, routing decisions, commands, client interaction and persistent data |
| [Java plugin adapters](/docs/proxy/java-plugins) | Optional BungeeCord and Velocity compatibility through Stratum and Shim |

The proxy does not simulate worlds, mobs or blocks. Those remain the responsibility of each backend. Installing a proxy does not synchronise inventories or backend permission systems.

## Java and Bedrock

The native Java protocol is currently Minecraft 26.3 (777). Older clients and backends are accepted through supported protocol routes, not by assuming every pair works. An incompatible server is skipped at login; an incompatible requested move leaves the player on their current server.

Bedrock support is built in and off by default. It includes NetherNet and RakNet transports and can bridge a player to a Java backend or delegate the session to Basalt Server. Read [Bedrock and versions](/docs/proxy/bedrock-and-versions) before choosing ports, forwarding and backend versions.

## Plugins

The native API is WebAssembly. [Kiln](/docs/proxy/wasm-kiln) builds `.bppkg` packages with a manifest, module and resources. Plugins can react to player events, decide routing, add commands, draw interfaces and talk to backends. The plugin host is enabled by default; sensitive capabilities require an explicit operator grant.

Optional Java adapters run BungeeCord and Velocity plugin bytecode through the embedded Shim JVM. They are separate from forwarding and from BungeeCord plugin messages. They are early compatibility layers, so test the specific jars you need.

<x-docs.callout type="warning" title="Keep the backend boundary private">
Authenticate at the proxy and configure the same forwarding scheme on each backend. Firewall backend ports so players cannot bypass the proxy, its whitelist or its protection. A forwarding setting alone is not a network firewall.
</x-docs.callout>

For a first network, keep the generated defaults, get one backend working, and add destinations one at a time. The [configuration reference](/docs/proxy/configuration) explains where each setting lives.
