Basalt Proxy reads commented TOML files under `config/`, or the directory passed with `--config <dir>`. Missing files are generated on startup. State belongs under `.basalt/`, and plugins under `plugins/`, relative to the working directory; changing `--config` does not move them.

## File map

| File | Purpose | Reference |
|---|---|---|
| `proxy.toml` | Listeners, authentication, runtime and plugin host | This page |
| `servers.toml` | Backends, groups, routes, health checks and status cache | [Routing](/docs/proxy/backends-and-routing) |
| `groups.toml` | Permission group definitions | [Groups](/docs/proxy/groups-and-permissions) |
| `commands.toml` | Command permissions, aliases, switches and custom text commands | [Commands](/docs/proxy/commands) |
| `messages.toml` | Kick and command messages | [Interface](/docs/proxy/interface#messages) |
| `server_list.toml` | MOTD, counts, icons, profiles and status relay | [Interface](/docs/proxy/interface) |
| `tab_list.toml`, `scoreboard.toml`, `boss_bar.toml` | In-game presentation and backend priority | [Interface](/docs/proxy/interface) |
| `animations.toml` | Shared text frames | [Animations](/docs/proxy/interface#animations) |
| `limits.toml` | Packet and chat/command spam limits | [Packet limits](#packet-limits) |
| `antibot.toml` | Connection protection and verification | [Antibot](/docs/proxy/antibot) |
| `remote.toml` | HTTP administration | [Remote API](/docs/proxy/remote-api) |

## Validation

Invalid TOML, unknown keys, wrong types and out-of-range values are reported with the file and setting. Startup stops instead of silently accepting a different configuration. For example:

```
config/proxy.toml: network.port is outside its integer range
config/proxy.toml: runtime requires low-water-bytes < high-water-bytes < session-buffer-bytes
```

Use the file generated by your executable as the starting point. `servers.toml` uses `[servers.<name>]` and `[routing] try`; older examples using `backends.toml`, `[backends]` or `routing.default` describe an older format.

## Hot reload

Run `reload` in the console, `/basalt:reload` with permission, or send SIGHUP on supported Unix systems. With `[reload] watch-files = true`, the proxy also watches the configuration and plugin directories.

| Can be reloaded | Requires restart |
|---|---|
| Server definitions, routes and groups | `[health]` and `[status-relay]` timings in `servers.toml` |
| Permission groups, commands, messages, UI and animations | `[runtime]`, `[admission]`, `[forwarding]`, `[logging]` |
| `limits.toml`, `antibot.toml`, `[access]` | `[bedrock]`, `[translation]`, `[plugins]`, `[reload]` |
| General brand, username pattern and startup-command definitions | `[general] enforce-secure-profile` |
| Network throttle, per-address/joins caps and trusted PROXY protocol options | Listener, online-mode, transfers, session-IP check and compression options |
| `[query]` listener configuration | `remote.toml` |

Startup commands are only executed when the process starts, even if their definition is reloaded. Existing sessions retain snapshots of relevant session and routing settings; do not expect every change to rewrite connections already in progress. Plugin reload restarts plugin instances and loses unsaved in-memory state.

A malformed candidate configuration is reported and rejected. Restart-only differences produce a message such as `changing [runtime] requires a restart`. Correct the file or restart deliberately; repeating reload does not apply a restart-only change. Presentation files are loaded by their own services, so do not rely on reload as a transaction spanning every subsystem.

## proxy.toml

A missing key uses its default. The tables below describe the shipped values.

### Network

`[network]` controls the public Java listener and authentication.

| Key | Default | Meaning |
|---|---|---|
| `bind` | `"0.0.0.0"` | Literal IPv4 or IPv6 bind address, not a hostname. |
| `port` | `25565` | Java TCP port, 1 to 65535. |
| `dual-stack` | `false` | Accept IPv4 on an IPv6 listener; requires an IPv6 bind address. |
| `online-mode` | `true` | Authenticate Java accounts with Mojang. False accepts offline identities. |
| `accept-transfers` | `false` | Accept transferred clients; transfers still authenticate. |
| `prevent-client-proxy-connections` | `false` | Include the public player IP in the Mojang session check. |
| `compression-threshold` | `256` | Client compression threshold in bytes. -1 disables, 0 compresses all; maximum 8388608. |
| `proxy-protocol` | `false` | Accept HAProxy PROXY v1/v2 headers from explicitly trusted peers. |
| `proxy-protocol-trusted` | `[]` | IPv4/IPv6 addresses or CIDR ranges allowed to supply a PROXY header. Must be non-empty when enabled. |
| `connection-throttle-ms` | `0` | Delay between logins from an address, up to 3600000 ms. 0 disables; loopback and status pings are exempt. |
| `max-connections-per-address` | `0` | Open connections from one address, including pings. 0 disables; maximum 65536. |
| `max-joins-per-tick` | `0` | Logins admitted at the final step per 50 ms. Excess waits. 0 disables; maximum 65536. |

<x-docs.callout type="warning" title="Authenticate at the public entry point">
Keep online mode enabled on a public network. Offline mode allows a client to choose another player's name. PROXY protocol only establishes the reported source address; it does not authenticate a Minecraft account. Trust only your own load balancers.
</x-docs.callout>

### General

`[general]` describes the proxy brand and login/chat policy.

| Key | Default | Meaning |
|---|---|---|
| `brand` | `""` | Brand sent on server reconfiguration. Empty uses Basalt Proxy; maximum 64 bytes. |
| `startup-commands` | `[]` | Console commands run in order once the proxy starts listening. |
| `username-pattern` | `""` | Additional ECMAScript regular expression for login names; empty adds no rule beyond vanilla name validation. |
| `enforce-secure-profile` | `true` | Require signed chat in online mode and advertise the policy in the server list. |

### Query

`[query]` is the optional legacy GameSpy 4 UDP status service, not the HTTP administration API.

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `false` | Enable the IPv4 query listener. |
| `port` | `25565` | UDP port. It can share a number with the Java TCP listener. |

### Runtime

`[runtime]` bounds session ownership, slow work and retained network buffers.

| Key | Default | Meaning |
|---|---|---|
| `io-loops` | `0` | 0 selects one per available logical core, clamped to 2..16. A fixed positive value supports 1..64. |
| `workers` | `4` | DNS/authentication workers, 1..64. |
| `max-sessions` | `4096` | Open session cap, 1..65536. Advertised slots are independently configurable in server_list.toml. |
| `max-pending-work` | `256` | Bounded worker queue, 1..65536. |
| `max-buffered-bytes` | `268435456` | Global retained network-buffer budget, 4096 bytes to 16 GiB. |
| `session-buffer-bytes` | `16777216` | Per-session ceiling, 4096 bytes to 16 GiB, no larger than the global budget. |
| `high-water-bytes` | `4194304` | Pause reads above this queued-byte threshold. |
| `low-water-bytes` | `2097152` | Resume below this queued-byte threshold. |
| `handshake-timeout-ms` | `10000` | Handshake deadline. |
| `login-timeout-ms` | `30000` | Overall login deadline, including authentication and backend connection. |
| `connect-timeout-ms` | `10000` | Deadline for a backend connection attempt. |
| `read-timeout-ms` | `30000` | Read inactivity deadline. |
| `write-timeout-ms` | `10000` | Deadline for a peer to accept queued output. |
| `update-checker` | `true` | Check for a newer release/nightly at startup and warn in the log. |

All deadline values support 1..300000 ms. Water marks must satisfy `0 <= low-water-bytes < high-water-bytes < session-buffer-bytes`. A slow peer pauses reads rather than growing a session buffer indefinitely.

### Admission

`[admission]` uses global and per-origin token buckets. Rates are tokens per second and bursts are bucket capacities.

| Key | Default | Meaning |
|---|---|---|
| `global-rate` | `5000` | Sustained login connection budget. |
| `global-burst` | `10000` | Global burst capacity. |
| `status-rate` | `2000` | Separate server-list request budget, so status traffic does not consume the login bucket. |
| `status-burst` | `4000` | Status burst capacity. |
| `origin-rate` | `10` | Sustained attempts per source IP. |
| `origin-burst` | `20` | Per-origin burst capacity. |
| `max-origins` | `65536` | Bound on tracked origins. New origins are refused when full until idle entries expire. |
| `origin-expiry-ms` | `60000` | Idle expiry, 1000..3600000 ms. |

Rates, burst capacities and the origin-table bound support 1..1000000. Connection admission and the [antibot](/docs/proxy/antibot) complement each other; disabling one does not disable the other.

### Forwarding

`[forwarding]` identifies the proxy when signing Basalt forwarding responses. See [Forwarding](/docs/proxy/forwarding).

| Key | Default | Meaning |
|---|---|---|
| `proxy-id` | `"proxy"` | Proxy identity, 1..64 bytes. |
| `key-file` | `".basalt/forwarding.key"` | Private Ed25519 key path, generated on first use. Keep it with backups of proxy state. |

### Logging

`[logging]` controls console and file logs.

| Key | Default | Meaning |
|---|---|---|
| `level` | `"info"` | trace, debug, info, warn or error. |
| `file` | `true` | Mirror logs under .basalt/logs/. |
| `keep-days` | `14` | Archive retention, 0..3650 days; 0 keeps forever. |
| `color` | `"auto"` | auto for terminals only, always or never. |

### Bedrock

`[bedrock]` enables the Bedrock transports. See [Bedrock and versions](/docs/proxy/bedrock-and-versions) for ports and identities.

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `false` | Enable Bedrock entry. |
| `port` | `19132` | RakNet UDP port and NetherNet TCP signaling port. |
| `transport` | `"both"` | both, nethernet or raknet. Newer clients require NetherNet. |
| `nethernet-port` | `0` | NetherNet game UDP port. 0 uses port when RakNet is off, otherwise port + 1. |
| `advertise-address` | `""` | Public game address to advertise behind NAT. Empty derives it from the address reached by the client. |
| `language` | `""` | Path to an official server jar or en_us.json for backend translation keys. Empty leaves raw keys. Nothing is downloaded. |
| `delegate` | `false` | Let a Basalt-forwarding backend serve the Bedrock session through the session envelope. |

Bedrock MOTD and counts come from `server_list.toml`. There is no `[bedrock] motd` key.

### Reload watcher

`[reload]` watches files; it does not remove the restart boundaries above.

| Key | Default | Meaning |
|---|---|---|
| `watch-files` | `false` | Watch configuration and plugin changes and reload once they settle. |
| `interval-ms` | `2000` | Polling interval, 250..600000 ms. |

### Translation

`[translation]` decides where version translation happens.

| Key | Default | Meaning |
|---|---|---|
| `mode` | `"auto"` | auto delegates to capable Basalt servers and translates other supported routes here; server only delegates or relays; proxy translates here; off requires matching protocols and does not offer the session envelope. |

For delegation use Basalt forwarding, protocol `"client"` or `"auto"`, and enable `session-envelope` on the Basalt backend. See [version support](/docs/proxy/bedrock-and-versions#who-translates).

### Access

`[access]` sets whitelist policy; entries themselves live in the database.

| Key | Default | Meaning |
|---|---|---|
| `whitelist` | `false` | Require a whitelist entry at login, except operators. Console whitelist on/off changes the running switch; startup follows this file. |
| `enforce-whitelist` | `false` | Also remove non-whitelisted, non-operator players already online when enforcement is triggered. |

### Plugins

`[plugins]` controls the [plugin host](/docs/proxy/wasm-plugins).

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | Look for plugins under plugins/. |
| `queue-size` | `256` | Queued plugin events, 1..65536. Full queues drop new work. |
| `packet-max-kib` | `256` | Largest packet exposed to listeners, 1..2048 KiB. |
| `packet-timeout-ms` | `25` | Bounded packet-listener wait and callback budget, 1..1000 ms. |
| `allow` | `{}` | Per-plugin grants of commands, network and packets. These must also be declared in the manifest. |
| `java-platform` | `{}` | For jars with both descriptors, choose velocity or bungee by plugin id/name or jar filename. |

```toml
[plugins.allow]
lobby_tools = ["commands", "network"]

[plugins.java-platform]
"example.jar" = "bungee"
```

Changing plugin-host settings requires restart. Replacing packages and running `reload` restarts plugin instances. The manifest's `storage` and `players_data` capabilities do not require an operator grant; see [plugin.toml](/docs/proxy/wasm-plugin-toml).

## Packet limits

`limits.toml` applies once a Java connection is in configuration or play. Handshake and login are governed by admission and deadlines.

```toml
[packets]
rate-limit = 500

[packets.drop]
"serverbound.command_suggestion_request" = 20

[packets.kick]
"serverbound.place_recipe" = 200

[spam]
chat-threshold-seconds = 10
command-threshold-seconds = 10
excluded-commands = ["help"]
```

The shipped `rate-limit = 0` disables the overall packet-rate kick. The drop and kick tables ship empty and cap individual current-protocol packet names per second, regardless of the client's version. Use a phase-qualified name when needed, such as `serverbound.play.keep_alive`. Drops discard excess packets; kicks disconnect the player.

Spam thresholds ship at 10 seconds each. `0` disables the corresponding kick. `excluded-commands` lists command names without `/` that do not count toward command spam. These controls are separate from the antibot's exploit scanner and limbo packet limits.

## Files and state

Back up `config/`, `plugins/` and `.basalt/` together. `.basalt/players.db` contains proxy player state and plugin data; it is not a backend inventory database. `.basalt/forwarding.key` is the private identity trusted by Basalt backends, and `.basalt/api.token` authenticates HTTP administration. Do not put these credentials in published examples or plugins.
